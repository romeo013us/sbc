# Ledger evidence ingestion (isolated candidate)
The ledger and outbox evidence row commit atomically. No entitlement action, financial delta, charge, refund, subscription access, or dispatch is authorized. Adapters must verify provider signatures, merchant/environment, payment identity, canonical tenant mapping and provider readback before calling the ingestor. The existing V1 contract does not encode payment/subscription identity or recurring period, so direct entitlement transitions are deliberately unavailable. The real MySQL acceptance workflow uses an isolated disposable database and injects an acknowledgement loss after a genuine commit. A fresh connection reconciles the immutable evidence and the outbox receipt; no write is automatically replayed. Both applications need a single explicitly configured authoritative writer database, provider adapters, entitlement decision policy, schema/lease verification and coordinated hosted acceptance before activation. Do not run against production.
