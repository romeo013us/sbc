# Shared financial schema foundation — isolated candidate

These four additive, namespaced MySQL 8 DDL steps are a versioned foundation, not an activated billing system. No provider handler, startup entrypoint or existing database is changed. Use a dedicated fresh autocommit pool, with no active transaction, and a real runtime writer-lease assertion. Both products must eventually point at one explicitly configured authoritative ledger database, not independent local ledgers. Read-only mode checks migration history, never applies DDL. The database advisory lock serializes participating migrators; an applying marker requires manual inspection and verified recovery if interrupted. Do not reset the marker or rerun DDL automatically. This runner supports only single CREATE TABLE migrations in this isolated namespace. It does not migrate existing application schemas or prove physical schema integrity; real MySQL acceptance, schema verification, writer fencing, backup/restore and boot integration are required. No entitlement mutation or outbox delivery is implemented. Do not deploy or run against production.
