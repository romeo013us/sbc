# SBC v65.2.0 Sovereign Core — Staging Track

This is a staged architecture increment, not a claim that production is already upgraded.

## Included work
- Durable-first event-dispatch design with an injectable ledger adapter.
- Kim patch proposal sandbox that syntax-checks and stages proposals outside active source files.
- An unpartitioned InnoDB event ledger and metadata-only proposal review table.
- Tests for duplicate suppression, path containment, syntax rejection, and active-file immutability.

## Required safeguards
The event adapter must enforce a database unique constraint and return success only after commit. Verify tenant authorization before dispatch. The ledger is not a payment ledger and must never be treated as proof of payment success.

The example partitioned schema is not used: MySQL partitioning restricts unique keys, and the provided partition/primary-key design is not safe to apply without server-specific validation.

## A/B/C rollout gates
A. Concurrency: staging-only replay of duplicate provider event IDs at controlled worker counts; measure p50/p95/p99 latency, memory, pool usage, queue depth, timeout count, and duplicate outcomes. Never spike live payment endpoints.

B. Kim sandbox: test path traversal, protected targets, malformed syntax, oversized patches, and verify active files remain unchanged. Proposals stay pending owner review; generated code is never executed by the staging module.

C. Database and backups: inspect actual schema/indexes/query plans read-only; verify tenant predicates; apply migrations only through the approved published-writer process after backup verification; restore to a disposable database and record recovery time.

## Release gates
- Run the new Node built-in tests and full `npm run test:all`.
- Review the actual MySQL adapter and tenant authorization before wiring to live routes.
- Verify GoDaddy runtime, MySQL version, backup permissions, and restore procedure.
- CI success is not proof of production deployment.

No live concurrency benchmark, migration, backup, restore, or production deployment has been performed by adding this plan.
