# Disposable MySQL inventory acceptance

The existing disposable MySQL 8 CI service now runs scripts/sbc-marketing-inventory-mysql.test.cjs after financial ledger and marketing read-model acceptance. The test creates the three candidate tables in the fixed loopback CI database only. It checks real lock ownership on two connections, concurrent unauthorized insert refusal, stale revision rejection, separate approval revisions, readback FKs, exact digest CHECK, tenant isolation, revoked review projection, lease handoff and used-source exclusion. It deliberately injects a permissive application guard to test the independent SQL gate. Creative review and HTTP verification are fixtures; no real publication or image approval is implied. This does not test abrupt disconnect or atomic cross-store revocation. No active migrations or runtime changes.

The retired v6538 patch-based test is replaced with execution of the current server no-DDL hydration branch in a VM. The healthy case, partial baseline and failed hydration cases pass locally on Node 22 against server blob 90b7231ed72452c5d98aa197487a8b9f8eb1166c. Existing writer unit tests passed 4/4. The MySQL integration file passed node --check; real MySQL is unavailable locally, so CI must establish the actual database result. Never activate the candidate schema based on syntax checks.
