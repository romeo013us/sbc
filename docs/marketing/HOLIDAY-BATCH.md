# Private holiday batch operator
Use the existing configured Creative Studio runtime with three completed, source-approved sbc-marketing jobs. Match the jobs to the three holiday slugs in the campaign bank; the operator must verify copy, dates and visual content. Configure the authentic owner-approved PNG and its independently verified SHA-256 via SBC_SOCIAL_LOGO_PATH and SBC_SOCIAL_LOGO_SHA256. Never use a fixture logo. Stop other processes before opening the local runtime and use a private output location outside web roots. Supply the complete authoritative priorSourceIds history (empty only when genuinely empty).
 
1. Input JSON has priorSourceIds and entries, each entry containing slug and jobId. Use exactly thanksgiving-2026-engagement, black-friday-2026-invest, black-friday-2026-growth. Run node scripts/stage-holiday-batch.cjs stage input.json /absolute/new-private-stage.
2. Open the actual three JPEG files from the private stage. Review exact bytes, content, logo, pricing, rights, accessibility and visual uniqueness. Create a separate approval JSON with priorSourceIds and entries containing slug, jobId, approvedSha256 and reviewVersion. Do not copy a stage receipt as an approval without human inspection.
3. Run node scripts/stage-holiday-batch.cjs package approval.json /absolute/new-private-release. This re-renders and requires exact approved hashes and current review versions. It produces release.zip, candidate-manifest.json and separate private-receipts.json. Do not upload private receipts or staging output. If the operation fails, discard partial private outputs. 
4. Upload only the reviewed public candidate files by an authorized website operator, then run verify-social-deploy.cjs against the manifest. Media readback is not publication authorization. Reconcile prior posts and actual current rights before posting.

The wrapper does not create jobs, prove ownership of a logo, certify complete history, compare perceptual similarity, validate live URLs, upload or publish. The CLI is a trusted offline command, not an exposed endpoint. Tests use actual FFmpeg and synthetic test images with injected review records; they exercise the two exported functions, not live SQLite or the hosted CLI. Only square feed JPEGs are generated by the existing staging engine. Do not count the 60-campaign plan as rendered media. No new live service, expenditure or deployment.
