# Marketing inventory persistence proposal and SELECT adapter

The adapter loadInventoryInputs(pool,{tenantId,bank,logoSha256,reviews,now}) returns input for existing projectInventory and planReplenishment. Only trusted server-side callers may supply authenticated tenant identity, canonical logo digest, campaign bank, current review store and a SELECT-only pool. It queries latest append-only revision per planned campaign/format and exact revision/digest readbacks, then complete bounded tenant source-use history. The actual Creative Studio review must still match the staged source and version; mismatches clear final approval and verification in the projected input. A used JPEG digest is treated as a reused source even if a different source ID produced it. Errors propagate; do not replace unavailable history with an empty list.

The three DDL statements in docs/schema-proposals/sbc-marketing-inventory.sql are proposals, not active migrations. Each would require its own checksummed migration coordinated with the shared core. DATETIME values must be UTC. Writers must be append-only and enforce exact immutable source, actual authorized final-byte approval, monotonically increasing revisions, live readback receipts and verified provider post IDs; no INSERT, UPDATE, migration, worker, HTTP request handler or publication capability is included. Enforce DB privileges and a genuine writer fence before adding mutations. Source history must be reconciled with actual existing provider receipts before activation. An exact digest is not perceptual similarity proof. Two SELECTs and SQLite review reads are not an atomic cross-store snapshot; the projection is advisory and publication must independently recheck current rights, review, complete history, slot reservation and actual public bytes.

Local tests use fixture SQL responses and review data; the authentication regression executes actual durable-key file handling and source checks on the exact current server. MySQL syntax/FK behavior, real review-store integration, production configuration, full consolidated CI and hosted operation remain unverified. No DDL executed, no customer data mutated, no real assets or posts generated.
