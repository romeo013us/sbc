# Marketing inventory read model

projectInventory in enterprise/creative-intelligence/marketing-inventory.cjs projects the 60 evergreen campaign slugs into 180 planned format slots (or up to 63 concepts including holidays). The caller must supply authoritative current SBC-only review, logo, final approval and HTTP readback evidence, plus complete prior source history. This is an offline read model, not an authorization boundary, persistent store, scheduler, or actual media inventory. It does not read public media, verify signatures or bytes itself, establish tenant scope, record platform publication, or reserve slots. It always returns publicationReady:false.

Each asset row includes slug, format, sha256, sourceAssetId, logoSha256, reviewVersion, currentReviewVersion, reviewState, finalApprovedSha256, verifiedAt (canonical UTC ISO or null). States distinguish missing, previously_used, logo_mismatch, review_required, final_review_required, readback_required, media_verified. Readback freshness is one hour as a conservative proposed operational default. A source can have multiple variants under one campaign; exact output digest duplicates and exact source reuse across campaigns are rejected. Distinct source hashes are not proof of perceptual uniqueness. Recheck current review, source history, rights and public availability at publish time. Never pass arbitrary user-supplied evidence into this projection as trusted.

CLI: node enterprise/creative-intelligence/social-jpeg.cjs JOB_ID --format landscape (or portrait/square). Omit the flag for square. Existing original logo and review requirements remain. The holiday batch CLI remains square-only. No deployment or publication included. Four focused regression tests cover the projection and CLI argument parser; full hosted CLI and persistent inventory integration remain to be accepted.
