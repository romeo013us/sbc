# SBC Command Center V66.56 — Build / SaaS / Company acceptance

## Release decision

**Status: NO_GO for final 9.5 certification.** Automated source, mock-provider browser, and disposable MySQL gates cannot prove the published GoDaddy deployment, real Square capture, or a genuine sale. Every subsystem must independently attain 95/100; the V66.55 evidence grader remains the only formal scoring protocol. This V66.56 diagnostic is read-only supplementary evidence.

## Track 1 — Engineering Build

- Verify GitHub commit and checked prebuilt receipt SHA before opening GoDaddy Preview.
- Update **Preview only** and confirm its actual running commit matches the source. Published remains unchanged until Preview acceptance.
- Confirm startup reaches HTTP serving with no missing catalogs, Mongo/MySQL writer lease failures, or disabled recovery guard.
- In authenticated desktop and iPhone sessions check all P0/P1 navigation, buttons, dialogs, inline status feedback, console exceptions, and 60-second-plus stability.
- Capture approved browser and API latency measurements and documented rollback steps.
- Independently back up current live MySQL and **restore to a separate nonproduction server**; preserve tenant boundaries and reconcile before any write operations. The automated CI test uses only three fabricated rows in the disposable `sbc_ci_disposable` database. That test **does not certify a production backup**.

## Track 2 — Commercial SaaS

- Use the existing GoDaddy owner-only diagnostics (GET) to establish correct runtime role, recovery/writer status, and Square readiness. Never place tokens in a bug report.
- In authenticated Preview, verify CRM customer create/edit/readback with nonproduction test fixtures only; check other-tenant denial, quote navigation, cancellation and failure feedback.
- Validate checkout link integrity and idempotency, webhook signature, **provider-confirmed capture** and paid-only fulfillment using Square's authorized Sandbox before seeking explicit approval for any live-dollar test.
- Test approved Twilio call, webhook authenticity and durable call log, consent and suppression behavior.
- Verify no Office Box vendor dispatch can start before captured payment and owner clearance.

## Track 3 — Operating Company

- Measure qualified leads with one definition and tenant filter; distinguish active/qualified/contactable/sales-ready cohorts from all CRM records.
- Reconcile actual Square captured gross, SBC ledger gross and accounting gross in **integer cents**, with Square fees and vendor costs reported separately.
- Calculate lead-to-close conversion using logged calls and paid orders; exclude won quotes, order value, mock revenue or unverified paid flags.
- Confirm a **real paying client** receives delivery and accepts it. Capture support outcomes, churn/renewal and actual margin.
- The first business sale, its collected cash and delivery evidence cannot be generated by a code deployment.
