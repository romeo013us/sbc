# Selected lead dossier and marketing capture read models

The existing authenticated Website Call Desk GET route accepts a selected customerId and returns a review-only salesDossier. The list path performs no per-lead queries. After asynchronous cache access, the route projects the current assignment and suppression state again. The existing browser panel loads only the selected record and escapes bilingual observations. The owner-approved calling script and existing manual call authorization remain unchanged. This is not a full Account 360 or Kim integration.

The snapshot reader is disabled by default. Provision the candidate cache table only after reviewed deployment acceptance; use an independent SELECT-only database identity and trusted TLS configuration. Set SBC_DOSSIER_CACHE_ENABLED to 1 only after verified offline cache ingestion and schema/permissions acceptance. The read pool requires SBC_DOSSIER_DB_HOST, SBC_DOSSIER_DB_USER, SBC_DOSSIER_DB_PASSWORD and SBC_DOSSIER_DB_NAME. It does not fall back to writer credentials. Snapshot records must be created by a trusted server-side process with authoritative lead and tenant mapping, UTC checked_at and validated evidence. That ingestion path is not yet implemented. Missing/invalid/unavailable cache evidence does not authorize a call or change the lead. No production configuration has been set.

The campaign summary reads the existing proposed attribution and campaign registry schema, joins the immutable event-key ledger, excludes noncapture and sandbox evidence and provider/account mismatches, and groups separately by currency. Exact decimal integer strings avoid JS precision loss. This is a gross attributed capture candidate report; no net settlement, refund reconciliation, causal ROI, or settled-order count is claimed. A trusted checkout/payment binding and transactional attribution writer are still required. The audit cache SQL is outside active migrations. The dedicated MySQL CI step applies proposals only after the original four migrations in a disposable database. No live migration, payment, outreach, public deployment or social publication is authorized by these changes.
