# Protected promotion cutover (disabled by default)

The workflow accepts exact base, candidate source, independently reviewed seal, staging run and review PR. It requires the core exact-base PR workflows and rejects unsuccessful additional runs recorded for that same PR/base/source. It verifies staging and recovery pin before and after protected approval. The write job uses only the dedicated environment credential, not the ordinary Actions token, and validates using trusted master code. The existing master publisher remains enabled until the repository variable SBC_ATOMIC_PROMOTION_ENABLED is explicitly set to true.

Before enabling: configure the sbc-release-promoter environment with required independent reviewers and master-only deployment branch policy; provision a dedicated narrowly scoped release actor credential in that environment; restrict a-sbc-master updates to that actor (no ordinary PR merges), protect candidate/recovery refs against unauthorized mutation and verify the rules through GitHub administration. Verify the workflow is dispatchable from the canonical/default workflow configuration. Do not enable the variable before these controls and a sealed master are confirmed. Validate the exact required CI inventory and any conditional domain/workstation checks for each release. Review changes to CI and release controls separately. The seal SHA must be independently read from the successful staging run and approved, not inferred from an arbitrary ref. The workflow does not prove that administrator configuration exists. The final read-only verifier and GoDaddy hosted acceptance remain separate. If master promotion succeeds but Preview advancement fails, reconcile the verified recovery ref without republishing raw source.
