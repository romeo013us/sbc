# SBC V66.60 — Customer Website / Command Center Bridge

**Scope:** customer website and SBC Command Center. The GoDaddy-managed sbcwebsites.com storefront is unchanged. Office Box remains postponed.

## Critical fixes

- `POST /api/web-lead`, `/api/portal/register`, and `/api/portal/login` no longer trust the GoDaddy host header as the website's tenant identity. They require a signed raw JSON request generated by the website's PHP backend.
- HMAC-SHA256 signature signs timestamp, `sbcmia.com`, HTTP method, path, raw body hash and 16 random bytes of nonce; five-minute freshness and bounded in-memory replay checks. The key must be at least 32 characters, never supplied in a browser form or kept in GitHub.
- New customers cannot claim CRM data attached to an existing email simply by self-registering; existing SBC clients contact staff for verified account activation.
- Customer login is scoped to the website's tenant **before** issuing a portal token. Staff portal account summaries, messages and internal customer actions require owner access plus tenant boundaries.
- Website `index.php` corrects registration's `contactName` field, card form names, sign/card contact capture, request-origin protection and avoids leaking portal bearer tokens in browser responses.
- Preserve existing $99/$199/$349/$699 website packages, Square checkout URLs, and all sbcwebsites.com links. Standalone Square payment links remain **separately reconciled**; a checkout redirect is not collected revenue.

## Deployment order (required)

1. Back up existing sbcmia.com `public_html/index.php`. Do not replace any other PHP pages unless separately tested.
2. Generate a **new independent 64-character random hexadecimal key** on a trusted machine. Never paste it into ChatGPT, an issue, a shared support ticket or the PHP file.
3. Configure `SBC_WEBSITE_BRIDGE_KEY` on GoDaddy **Published Command Center** and the *website PHP host*, with the **same exact secret**. For PHP hosting that cannot inject environment variables, put the key in `../sbc-website-bridge.key` outside `public_html`, permissions 0600, and do not share it through public web.
4. Update **Preview** from `main` and check the runtime starts without regressions. Preview stays read-only and **must not be used to submit actual customer leads**.
5. When ready, deploy Published through the usual owner-approved GoDaddy flow. Do not lift recovery gates, alter the writer role or run DDL for this release.
6. Upload the supplied standalone **index.php** to sbcmia.com/public_html **only after both hosts are configured**. Do not place the PHP file in the Node.js ZIP.
7. Check portal registration with a newly created **noncustomer, designated staging identity** only in a safe test environment; do not create synthetic leads in the authoritative production CRM. Test real website quotes with explicit consent and then confirm tenant=1 lead/duplicate handling using owner read-only UI.
8. Check email fallbacks and Square standalone payment link reconciliation separately. No Square charge or vendor dispatch was executed by CI.

**Expected failure before key setup:** PHP site may display normally but customer registration/login will return `503`. CRM form notifications can fall back to email if configured; they do not silently claim a lead was saved. That is deliberate fail-closed behavior.
