# Social asset deployment readback and campaign links

After independently approved, original-logo social JPEGs are uploaded to the authorized SBC website location, run node scripts/verify-social-deploy.cjs candidate-manifest.json. It emits a timestamped receipt to stdout only if every expected JPEG at the exact fixed SBC HTTPS URL returns HTTP 200 with matching MIME, length and full SHA-256. The verifier bounds asset counts and streamed bytes and rejects redirects. It does not upload or extract files, re-approve a creative, validate current rights, or modify the source manifest. A mediaVerified receipt is time-limited evidence of byte availability, not permission to publish; recheck owner review, history, current HTTP availability and provider acceptance when publishing. It deliberately retains publicationReady:false because HTTP availability alone is not publication authorization.

buildCampaignLink creates fixed-origin SBC home page UTM URLs using the actual platform, validated campaign slug and full asset digest. These are untrusted marketing hints, not signed financial evidence, a unique visitor identifier or proof of revenue attribution. Server-side campaign registration, consent-aware session capture, durable lead/checkout association, payment-object reconciliation and reporting remain separate integration work. No live payment, entitlement or posting routes are modified. Tests use synthetic JPEG markers and injected responses to verify the transport boundary; actual JPEG decoding is performed upstream by the existing FFmpeg staging engine, not here. Real hosted HTTP acceptance is required before rollout.
