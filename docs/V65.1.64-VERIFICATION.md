# SBC OS V65.1.64 — Verification Runbook

## Scope
V65.1.64 targets the dashboard instability in which panels move or appear combined after the page has been open. It disables the global section-reordering behavior, removes fragile numeric child-position layout selectors, versions the static asset cache, and aligns the package/release identity.

## Automated checks
The GitHub Actions workflow `.github/workflows/sbc-v6565-regression.yml` runs:
1. `npm ci` against the lockfile.
2. Node syntax validation for `bootstrap.js`.
3. The V65.1.64 dashboard stability regression test.
4. `npm run build` to verify the complete source bundle and sequential hotfix chain.
5. `npm run test:all` for the full regression suite.

## GoDaddy acceptance checks
After GoDaddy publishes V65.1.64:
- Confirm startup log says `Launching SBC 65.1.64`.
- Confirm effective runtime role and database fingerprint are the expected production values; do not infer this from UI labels alone.
- Hard-refresh the browser, keep the dashboard open for at least 10 minutes, and confirm sections remain in place.
- Check browser console and network requests for JavaScript exceptions, repeated requests, or stale asset responses.
- Reconcile active leads, paid orders, recorded revenue, and fulfillment counts against the authoritative database before relying on the dashboard for business decisions.

## Safety boundary
The dashboard hotfix does not change database records, bypass tenant isolation, disable recovery safeguards, or authorize financial mutations. A `readonly` runtime must not be changed to a writer role until the authoritative database baseline and exclusive writer lease have been verified.
